# CampGear Compare 网站优化 SOP：30 天自动执行计划

执行周期：2026-10-19 至 2026-11-17  
默认执行时间：每天 09:00（Asia/Shanghai）  
核心目标：增加合格自然访问，提高“指南 -> 比较 -> 产品详情 -> 官方站”使用率，并建立可重复的内容与分发流程。

## 一、30 天目标

- 保持全站生成、内部链接、结构化数据和分析事件测试通过。
- 将最近 28 天 GA4、GSC 和引用域名数据补齐；无法访问后台时明确记录阻塞，不填估算值。
- 优先优化已有展示和点击的 Naturehike、Big Agnes 页面，不无依据增加第三个集群。
- 每周至少改善 1 个真实用户路径，并用事件验证，而不是只改文字。
- 完成 1 个季节性、可引用的数据资产或现有数据工具升级。
- 只在证据满足门槛时新增页面；30 天新增指南上限 4 篇，默认目标为 0–2 篇。
- 所有外部推广使用独立 UTM；浏览量不算成功，有效访问或真实引用才算。

## 二、每日自动执行流程

每天按以下顺序运行，单日默认控制在 60–90 分钟：

1. 读取本文档、`docs/growth-status.md`、`docs/growth-metrics.csv`、`docs/growth-experiments.md` 和最近的 Git 状态。
2. 根据上海日期计算 Day：2026-10-19 为 Day 1，依次递增；同一天不得重复执行已完成任务。
3. 检查上一日是否有 `NEEDS_USER`、测试失败或未完成的高优先级事项；必要时替代当天低优先级新工作。
4. 只修改与当天任务直接相关的文件，不覆盖用户或其他任务留下的改动。
5. 运行与改动匹配的测试。网站生成类改动至少运行：
   - `npm test`
   - `python3 scripts/validate_generated_site.py`
   - `python3 scripts/audit_structured_data.py`
   - `git diff --check`
6. 在 `docs/website-optimization-sop-log.csv` 追加一行，记录日期、Day、结果、交付物、测试和下一步。
7. 只有存在有意义且测试通过的改动时，才创建一个范围清晰的提交并推送 `origin/main`。无改动时记录 `NO_CHANGE`，禁止空提交。
8. 用直白中文汇报：做了什么、为什么有帮助、验证结果、是否需要用户操作。

## 三、自动化权限边界

### 可以自动执行

- 读取本地项目、分析数据、修改网站代码和内容。
- 生成已审核数据派生的表格、图表、内部链接和站内说明。
- 运行测试、构建、SEO 检查和本地视觉检查。
- 在测试通过后提交并推送与当天任务直接相关的文件。
- 生成邮件、Pinterest、YouTube、社区回答和编辑外联的草稿。

### 必须停下并标记 `NEEDS_USER`

- Google、AliExpress、Amazon 或其他账号登录、验证码和身份验证。
- 发送邮件、提交表单、发布社交内容、社区回复或联系第三方。
- 付费、购买广告、订阅服务、修改账号权限或启用联盟链接。
- 删除已发布页面、大规模 `noindex`、重定向或一次清理超过 10 个 URL。
- 数据不确定、来源失效或事实抽查错误率超过 5%。

## 五、判断门槛

- CTR 实验：至少运行 14 天，除非出现明显技术问题，否则不提前下结论。
- 新指南：目标集群已有点击，查询意图明确，且能提供现有页面没有的决策价值。
- 数据资产发布：抽查事实错误率低于 5%，方法、来源、日期和限制完整。
- 渠道继续：14 天内至少获得 1 次可归因站内有效事件、真实回复或引用。
- 联盟 CTA：账号已批准，并达到 100 个高意图会话或 50 次 Modal 打开后再判断。
- 页面清理：每批最多 10 个 URL，保留清单和回滚路径，观察后再扩大。

## 六、成功指标

主要指标：

- Organic sessions 与 engaged organic sessions
- GSC clicks、impressions、CTR 和平均排名
- `compare_selected`、`product_modal_open`、`outbound_click`
- 有效访问占比和新增相关引用域名

诊断指标：

- 页面数量、社交曝光、视频播放和无行为的访问量
- 单次测试分数或未经现场数据验证的性能提升

计划的目标不是每天都改代码，而是每天减少一个有证据的增长瓶颈。
